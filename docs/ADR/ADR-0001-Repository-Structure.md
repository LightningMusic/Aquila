# ADR-0001: Repository Structure

## Status

Accepted

## Context

Project Aquila needs one canonical location for source code, tests, build
tooling, configuration, and documentation that stays stable as the number
of subsystems grows (SRS Section 9.3, GP-004 Modular Design, GP-007
Expandability). The deployment USB is a generated release artifact, not
the development environment (SRS Section 9.4) — the repository must not
assume the USB's layout, and the USB's layout must not leak requirements
back into how the repository is organized.

## Decision

The repository follows a `src/`-layout Python project, matching SRS
Appendix A:

- `src/` holds one top-level package per subsystem (`inspection/`,
  `recovery/`, `preparation/`, `provisioning/`, `bootstrap/`,
  `deployment_controller/`, `inventory/`, `benchmark/`, `networking/`,
  `hardware/`, `bios/`, `logging_engine/`, `config/`, `common/`,
  `cli/`, `technician_console/`, `workflows/`, `core/`, `api/`,
  `interfaces/`, `models/`, `services/`), each with a single, clearly
  defined responsibility (GP-004).
- `configs/` holds runtime YAML configuration, kept external to
  application logic (GP-003, REQ-CONF-002).
- `scripts/` holds the Build System — the tooling that turns this
  repository into deployment USB media (SRS Section 9.15) — never the
  reverse.
- `tools/` holds developer-facing tooling that supports the engineering
  process itself (e.g. requirement traceability checking) rather than
  being part of the shipped product.
- `tests/` is reserved for structured test suites as the project grows;
  today's `run_tests_*.py` files at the repository root predate this
  reservation and are treated as the current, working test suite rather
  than being force-migrated before their replacement is designed.
- `docs/` holds the SRS, Architecture Decision Records, and other
  project documentation, per GP-010 (Documentation First).
- `usb/phase1/` and `usb/phase2/` are placeholders for boot-media
  templates/scaffolding the Build System assembles onto the generated
  image; they are intentionally not populated with generated media
  itself, which is a release artifact and does not belong in version
  control (SRS Section 9.4).
- `typings/` holds local type stubs (currently `wmi`) needed for strict
  static type checking where a third-party package ships without its
  own.

## Consequences

- A `src/`-layout means the package is never importable by accident from
  the repository root without first being installed or having `src/`
  added to `sys.path` — this is the layout's well-known trade-off, and
  is accepted deliberately: it is what makes `pyproject.toml`'s
  `[tool.setuptools] package-dir = {"" = "src"}` configuration
  meaningful, and it matches how `run_tests_*.py` and `tools/`
  scripts already add `src/` to `sys.path` explicitly.
- Every new subsystem gets its own `src/<name>/` package rather than
  being folded into an existing one, even when small, so responsibility
  boundaries stay legible as the project grows (GP-004, GP-007).
- The USB's own on-media layout (`phase1/`, `phase2/`,
  `reports/` — see `common/constants/deployment.py`) is generated by
  the Build System from this repository's `src/` and `configs/`; it is
  never checked in as a build output.
